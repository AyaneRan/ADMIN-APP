# 小売向け店舗マネジメントアプリ 多店舗拡張仕様

最終更新: 2026-09-07  
前提: 初期リリースは単店舗。将来のマルチ対応を同時に設計しておく。

## 1. 多店舗化の原則

- 全テーブルで `store_id` を持つ（単店舗時は1値固定）  
- 店舗横断分析は同じ集約粒度で実装する  
- 共通マスタ（カテゴリ・税率・決済・経費科目）は基本的に会社共通で運用  
- 権限・監査は `store_id` コンテキストを明示的に扱う

## 2. 共通で必要な機能

### 2.1 店舗比較
- 画面候補: `GET /reports/store-comparison`
- 比較対象
  - 売上, 粗利, 欠品率, 在庫回転率, 人件費率
- 表示条件
  - 単店舗時: 「比較不可」と明確に表示
  - 複数店舗時: 任意店舗選択 + 店舗全体ランキング
- アクセス
  - OWNER / MANAGER のみ閲覧可能

### 2.2 店舗横断在庫
- 画面候補: `GET /inventory/cross-stores`
- 表示
  - 商品単位で店舗別在庫、在庫合計、最適補充先候補
  - 在庫不足店舗の優先度ソート
- 運用
  - 単店舗時は隠し項目として非表示（将来有効化）
  - 将来の発注連携 API 追加時まで、更新は各店舗在庫画面で実施

### 2.3 マスタ共通
- 店舗間共通
  - 決済種別: `payment_method`
  - 税率: `tax_rate`（税改正対応日付を将来追加可）
  - 経費科目: `expense_category`
  - 商品カテゴリ: `product_category`
- 店舗ごとの差分
  - 原価/売価/最低在庫: `products` 側で店舗依存

## 3. フェーズ移行（確定）

- Phase 1（現行）
  - `stores` を固定1件として運用しつつ、全APIに store_context を要求
- Phase 2（開発候補）
  - ログイン時に `store_id` 選択を許可
  - 店舗比較・横断在庫を閲覧可能化
- Phase 3（運用）
  - 横断採点レポート（店舗別KPI、全店総括）  
  - 店舗跨ぎ承認の導線（例: 給与・経費の集中承認）

## 4. 画面変更方針（既存画面）

- ダッシュボード
  - 単店舗: 現行カード + 自店のみ表示
  - マルチ: 店舗切替/比較トグルを追加
- 在庫一覧
  - 単店舗: 店舗在庫のみ
  - マルチ: 比較タブ追加（`inventory/cross-stores`へのリンク）
- 店舗比較
  - 画面ルートは維持し、単店舗時は空状態メッセージに切替

## 5. データ整合性制約（重要）

- 月次締めのロックは `store_id` 単位で管理
- ロック済み月の更新は原則不可（参照のみ）
- POS自動取込・手入力補正とも `store_id` と `source_key` を必須
- 監査ログは `store_id` + `entity_type` + `action` で必ず検索可能に
